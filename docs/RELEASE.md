# Release Policy

Use semantic versioning for public APIs and app releases where practical. Keep CHANGELOG.md current with user-visible changes, breaking changes, migrations and known limits.

Release gates: product acceptance; security/privacy review; unit/integration/contract/E2E tests; migration compatibility; observability/runbooks; backup restore; support ownership; canary/rollback; legal, insurance and operational approval for launch geography.

Release notes include summary, user impact, features, fixes, breaking changes, migration, known issues and support contact. Never announce proposed or undeployed features.
